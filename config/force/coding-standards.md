# 编码规范

适用于源码、SQL、注释和关键配置的编写、修改与审查。

## 源码排版

遵循项目格式，独立语句分行、代码块按层级展开；格式整理限于修改范围，不改变行为。

## 复用规范

- 修改前检索同类实现和共享入口，已有适用能力直接复用；不足时优先扩展，不照搬违规实现或在消费方重写。
- 相似能力第二次出现时判断复用。职责相同、随同一规则变化且边界适合时收敛；语义、生命周期、分层或抽象成本不同则说明具体取舍，暂缓时给出复评条件。
- 共享改动追踪消费者，清理已迁移的重复实现；交付说明关键复用入口及必要例外。

## 异常处理

- 区分业务拒绝、可恢复失败和系统故障；仅在能够恢复、转换或补充上下文时捕获，保留原因链。
- 不吞异常或将失败伪装为成功、空数据和默认值。降级须有适用条件和明确语义。
- 复用统一异常与响应入口，对外反馈符合契约，不暴露堆栈、凭据和敏感实现细节。

## 日志与诊断

- 复用日志及请求关联机制，清理临时调试输出；CLI 输出遵循其契约。
- 系统故障由最终处理边界记录必要上下文、堆栈和原因链，避免沿途重复打印；业务拒绝、取消等按语义选级别。
- 保留定位所需标识，控制频率和体积，不直接打印完整请求、大对象或敏感信息。

## 输入、安全与权限

- 在可信边界校验输入、身份、功能及数据权限；客户端校验、隐藏按钮或提交的归属字段不能代替服务端判断，无合法依据时拒绝受保护操作。
- 外部输入进入 SQL、命令、路径、HTML 或外部地址时，使用对应的参数化、编码与访问限制，不用字符串拼接或通用转义替代。
- 真实凭据使用项目配置或密钥管理入口，不硬编码到源码、测试数据或交付物；敏感数据按用途最小化处理，日志、响应和交付物脱敏。

## 事务、并发与幂等

- 多步写入明确不变量和事务边界，异常按预期回滚；远程副作用和跨资源部分成功须有恢复、补偿或接管方式。
- 并发写入和状态迁移使用条件更新、约束或同步机制，不能仅凭先查后写保证正确。
- 重复提交、回调和消息重投须有业务去重范围、幂等判据及重复结果；按钮禁用或单进程标记不能提供跨实例、重启后的保证。

## 外部调用与异步任务

- 调用有超时和资源边界，重试有依据、上限及停止条件。超时可能已成功，有副作用的重试先核对幂等或查询结果。
- 异步任务有可观察的失败出口和完成判据，处理适用的重复、乱序和部分失败，明确失败状态及重试、补偿或接管入口；受理或发送成功不等于业务完成。
- 传播取消和中断，停止关联工作并释放资源，不吞信号后继续执行或重试。

## 兼容与变更控制

- 接口、字段、配置和持久化格式变化须检查消费者、历史数据及新旧版本共存，明确默认值、读写与迁移行为。
- 破坏性变化有明确需求或授权；重构保持约定行为，局部修复不夹带无关调整或擅改业务规则。

## 数据与配置语义

- 时间、金额、数值和跨系统转换明确时区、单位、精度、舍入、范围及序列化语义；区分缺失、空、零和非法值。
- 必要配置缺失或非法时明确报错或按契约降级；默认值有依据，不猜测环境、安全边界和业务结果。

## 性能与资源

- 按输入规模检查处理量、内存、事务范围、查询与索引；采用适用的分页、分批、流式和批量调用，避免 N+1、重复计算及大对象一次性加载。无法批量时说明依据和规模边界。
- 并发、队列和连接池根据配置、运行约束或负载依据确定容量、等待上限及超限处理；缓存和长生命周期集合有容量或淘汰依据，明确刷新、失效、旧值可用性及写入、配置变化后的一致性。
- 连接、流、锁、任务、计时器和订阅有所有者及释放时机，覆盖正常、异常、取消和退出；借用方不关闭共享资源。
- 长操作遵守请求线程、事件循环或 UI 线程的响应预算，必要时分批或调度；不笼统禁止同步执行。

## 页面实现与复用

界面风格、组件、布局、主题和视觉改动遵守有效 `DESIGN.md`；需要视觉设计时使用 `frontend-design`。纯后端任务不加载页面规范或设计技能。

分别检查结构、状态与交互、样式与 token、工具的复用。差异通过已有属性、插槽、配置或变量表达；组件外壳或相同 token 不能代替内部逻辑与状态样式的复用。

## 写SQL时

以下适用于独立交付或执行的 SQL 脚本。

- 默认命名 `{sql-purpose}.sql`。变更脚本说明用途、目标库及对象、前提、执行顺序、重跑限制、恢复方式或不可回滚原因；交付给出路径、执行时机和影响。
- 写入前用只读查询或预检核对对象、条件和预期影响；结构变更核对当前定义，全量操作须明确意图。
- 明确重跑应跳过、覆盖、继续或拒绝并落实检查；部分成功能识别已完成范围并安全恢复，不默认整份重跑。
- 变更前后核对数量、关键值、业务约束或结构，解释预期差异并处理残差；退出码或行数一致不足以证明正确。
- 文件总体、字段和执行语句或逻辑段均有必要注释，说明业务含义、约束、目的及前提。

## 写注释时

- 本次涉及的类、方法、实体字段、关键配置和 SQL 必须检查并补齐必要注释，修正失效内容；命名直观或历史无注释不能免除。
- 复杂业务、状态、权限、兼容、性能取舍、异常兜底及外部契约须说明依据和适用边界；外部文档不能替代代码附近的必要解释。
- 用清楚的命名和结构表达意图，注释补充原因和限制，不复述代码，也不代替修复错误行为。
