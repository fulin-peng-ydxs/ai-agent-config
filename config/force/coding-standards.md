# 编码规范

## 文档边界

本文面向编写、修改或审查代码的 AI Agent，统一维护跨项目的源码排版与复用、异常与日志、安全边界、数据一致性、外部调用、兼容、数据与配置语义、性能与资源，以及页面实现、SQL 和注释要求。项目结构、业务口径、日志框架、错误码、超时数值及其他技术栈细则由有效项目规范维护；协作授权、Git 和交付要求由 [AI 协作约束](collaboration-rule.md) 维护，页面设计契约与技能启用条件见其 [写页面时](collaboration-rule.md#写页面时)，验证要求由 [测试规范](testing-standards.md) 维护。

编写、修改或审查代码（含 SQL、注释及关键配置）时必须读取本文；代码改动实施前同时读取测试规范。本文是编码要求的唯一全局正文，变更时同步受影响的入口和技能引用，不在技能或其他工具目录维护正文副本。

## 源码排版

- 遵循项目现有格式规范，不将多条独立语句挤在一行，代码块按层级展开；格式整理限于本次修改范围，不改变业务行为。

## 复用规范

- **查入口**：修改前读取适用规范并检索同类实现，定位共享入口；以有效规范为准，不照搬已有违规写法
- **用入口**：已有适用能力必须直接消费；不足时先使用既有扩展点或扩展共享入口，禁止复制或在消费方重写同类能力
- **新增门槛**：无适用入口时才新增；同职责能力第二次出现须收敛到共享入口，确因语义、生命周期或分层边界不能合并的，说明依据。遵守项目结构与编码约定，避免无必要的依赖、抽象和硬编码
- **查消费方**：共享改动须追踪受影响的使用点，清理已迁移的重复实现并验证；交付说明复用入口及必要例外。规范变更须反查并消除旧规则冲突

## 异常处理

- 按契约区分业务拒绝、可恢复失败和系统故障；仅在能够恢复、转换或补充必要上下文时捕获异常，无法处理时交由既有上层入口处理。转换异常须保留原因链，不吞异常，不将失败伪装为成功、空数据或默认值；约定的降级须明确其适用条件及结果语义
- 复用项目统一异常与响应入口，对外提供符合契约的错误分类和可理解反馈；不得直接暴露内部堆栈、敏感实现细节或凭据。内部诊断信息按下节记录，不以隐藏对外细节为由丢弃故障依据

## 日志与诊断

- 应用运行代码复用项目日志入口及关联请求机制；临时调试输出交付前清理，命令行工具约定的标准输出和错误输出按其契约处理
- 需要诊断的系统故障在承担最终处理责任的边界记录必要上下文、异常堆栈及原因链，避免仅记录异常消息或沿调用链重复打印同一故障；业务拒绝、预期取消等按实际语义选择级别，不一律作为系统错误输出堆栈
- 日志保留定位所需的操作、业务标识和关联信息，按本次用途控制级别、体积及频率，避免在高频循环中输出大量日志或直接打印完整请求、大对象；敏感信息遵守下节保护要求

## 输入、安全与权限

- 在可信边界校验外部输入的类型、范围、格式和业务约束，以及身份、功能权限和数据权限；不以客户端校验、隐藏入口或客户端提交的用户、租户、归属字段代替服务端可信判断。无合法身份或权限依据时拒绝受保护操作，不默认放行
- 外部输入进入 SQL、命令、文件路径、HTML 或外部地址等执行、解释及访问上下文时，使用对应的安全接口和校验；不以简单字符串拼接或通用转义代替该上下文需要的参数化、编码、路径或访问范围限制
- 真实凭据和密钥使用项目既有配置或密钥管理入口，不硬编码到源码、测试数据或交付物；敏感业务信息按用途最小化读取、存储和展示，在日志、错误响应及诊断材料中按项目规则脱敏，不直接输出真实令牌、密码和密钥

## 事务、并发与幂等

- 多步写入先明确业务不变量、原子性和事务边界，保证适用异常能够触发预期回滚；数据库事务不能覆盖的远程副作用或跨资源操作，须明确部分成功后的恢复、补偿或人工接管方式，不用捕获异常继续返回成功掩盖不一致
- 涉及并发修改、状态迁移或资源竞争时，在实际写入边界落实适用的条件更新、约束或同步机制；不能仅依赖先查询后判断保证唯一性、状态合法性或防止覆盖
- 涉及重复提交、回调、消息重投或重试时，明确业务去重范围、幂等判据和重复请求的结果；防止重复副作用，不将前端按钮禁用当作服务端去重，也不将单进程内的临时标记当作跨实例或进程重启后的幂等保证

## 外部调用与异步任务

- 外部调用使用适用的超时和资源边界；重试须有可重试依据、次数或总时限上限及停止条件。超时不等于操作未成功，重试前须核对幂等、去重或结果查询机制，不对未知结果的有副作用操作盲目重试
- 异步任务须有可观察的失败出口和明确的完成判据；按实际采用的机制处理适用的重复、乱序和部分失败，不把提交成功、消息已发送或任务已受理等同于业务完成。失败后的状态、重试、补偿或人工接管须能够定位，不因采用异步而丢失错误
- 按运行时及项目契约传播取消和中断，并停止或释放关联工作与资源；不得吞掉取消信号后继续执行或无条件重试

## 兼容与变更控制

- 修改接口、字段、配置或持久化格式时，追踪受影响的调用方、历史数据及适用的新旧版本共存场景，明确默认值、读写和迁移的兼容行为；破坏性变化须有明确需求或授权依据，不静默改变已有契约
- 重构保持约定行为，允许变化须能追溯到本次需求；局部修复不夹带无关行为调整，不为消除错误而擅自改变业务规则。替换入口后的消费者迁移和失效实现清理按复用规范执行

## 数据与配置语义

- 涉及时间、金额、数值或跨系统转换时，明确适用的时区、单位、精度、舍入、范围和序列化语义；区分缺失、空值、零值与非法值，不以隐式转换或真假值判断合并业务含义不同的输入
- 必要配置缺失或非法时显式报错，或按明确契约降级；可选配置的默认值须有业务或项目依据，不用猜测值静默改变目标环境、安全边界或业务结果

## 性能与资源

- 考虑数据量、调用频率、事务范围、查询复杂度、缓存影响、资源释放和重复计算
- 避免 N+1 查询、大对象一次性加载、重复远程调用、无限增长集合、阻塞式长任务和资源泄漏

## 页面实现与复用

- 前端按结构、状态/交互、样式/token、工具分别核对复用；只套共享组件外壳、内部另写同类逻辑或状态样式，不算完成复用。已有共享规则的差异通过其属性、插槽、配置或变量表达；使用相同 token 不等于复用了状态配方

## 写SQL时

- 涉及数据库变更、初始化数据、字典、菜单、权限、配置或迁移 SQL 时，写清 SQL 文件路径、用途、执行时机、影响范围、回滚方式或不可回滚原因
- SQL 默认命名为 `{sql-purpose}.sql`
- SQL 文件必须有注释、包括总体、字段、执行语句的注释，说明用途、影响范围、前置条件、回滚方式或不可回滚原因

## 写注释时

- 方法、实体、类等关键代码或关键的配置信息必须有必要的注释说明，满足人工可读性
- 优先用命名和结构表达意图，不写复述代码的低价值注释
- 复杂业务规则、状态流转、权限边界、兼容逻辑、性能取舍、异常兜底、外部系统约束必须注释
