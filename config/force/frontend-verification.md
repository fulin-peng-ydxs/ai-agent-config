# 前端验证规范

## 文档边界

本文维护前端开发、原型制作、开发计划和专项审核共用的验证覆盖选择、证据有效性与验证完成条件。具体产品要求来自用户要求和有效项目契约，专项判定标准由相应技能及其清单维护；本文不是全部页面测试项的总清单，不另立布局、视觉或交互设计规则。

仅在需要安排验证、采集或解释证据时读取。各技能按任务读取自己的专项清单；需要体验判据时使用 `frontend-ux-audit` 的相关清单，不因读取本文启动全部专项审核。业务计算、权限策略、数据一致性与后端异常闭环由领域、服务或接口测试验证，页面证据只证明可观察结果。工具选择、服务保护和测试执行边界沿用 [AI 协作约束](collaboration-rule.md)。

## 范围与能力

- 继承用户指定范围及当前任务上下文。局部修改或 diff 验收覆盖受影响行为和消费者；只有独立的全局审核且没有范围线索时，才按审核技能默认范围执行。
- 先确认目标视口、输入方式和所用平台能力。通用任务、状态、长列表、数字呈现与导航恢复适用于桌面和移动端；触摸手势、软键盘、原生输入仅在相关能力受影响时检查；安装态、Service Worker 与离线缓存仅在项目使用这些能力时检查。
- 响应式或可安装不自动等于移动目标；视口宽度也不能证明设备或输入方式。视口范围不明时说明假设，不把未声明的移动支持列为阻塞项。
- 验证选择服从项目要求及改动风险，优先能证明问题的最低层。不因改共享文件就默认全站回归、全量构建或实体设备测试。项目明确要求但未完成的验证仍须报告。
- 制定计划时只把适用场景和通过条件安排到验证任务；编写规范但尚无实现时检查规则可执行性，不要求为验证而先开发页面。计划、已确认设计与已通过实测分别标明，不能互相替代。

## 按改动风险确定验证覆盖

先从用户要求、有效项目契约及相关专项技能取得适用判据，再关联本次改动可能影响的行为与场景。在现有计划或简短说明中写清“受影响行为 / 风险 → 验证场景 → 判据来源与通过条件 → 证据方式”，不用另建报告。项目明确要求的视口和场景仍须覆盖；除此之外，按风险补充内容与状态，不能只复查固定分辨率。

下表提供选择场景和采集证据的线索，不直接规定产品应如何呈现或操作：

| 改动涉及 | 可选场景维度 | 证据采集重点 |
|---|---|---|
| 高度、占比、flex/grid、空间分配 | 可用空间与内容量变化；必要时组合空间充足/受限与短/长内容 | 各区域实际尺寸、剩余空间、内容与操作的几何边界及滚动范围 |
| 宽度、文案、列或字段布局 | 受影响的窄容器、长名称或极值、换行与溢出临界点 | 文字与控件边界、折行与溢出表现 |
| 滚动、固定或吸附定位、弹窗与抽屉 | 相关滚动位置、触发滚动前后、展开与关闭、约定的退出及恢复路径 | 滚动所属区域、末端内容与操作位置、退出及恢复的实际结果 |
| 条件显隐、异步内容、状态反馈 | 相关内容出现、更新、移除；涉及的加载、空、成功、失败及重试路径 | 状态转换前后的几何变化、反馈内容、恢复操作及其结果 |
| 颜色、主题、组件交互样式 | 受影响的支持主题，以及相关默认、悬停、聚焦、选中、禁用等状态 | 实际计算样式、渲染结果与交互状态的对应关系 |
| 输入、焦点、弹层交接或原生控件 | 相关输入方式下进入、切换、取消和恢复；涉及时覆盖软键盘展开与收起 | 实际命中、焦点轨迹、输入值、可见区域与退出操作的结果 |
| 路由、缓存页面、导航与恢复 | 首次进入、离开或隐藏、返回及再次操作；涉及时包含延迟数据到达 | 条件、草稿、位置、浮层与延迟结果在转换前后的实际状态 |
| 共享组件或全局样式 | 按下文消费者追踪结果选择有实际差异的使用点 | 消费点、局部覆盖、容器和状态差异及对应操作结果 |

表格不是每次必跑的清单，也不因出现某种 CSS 写法就要求遍历全部组合。只选择与实际影响有因果关系的维度；已排除的风险无需逐项建表，但影响验收范围的取舍须说明依据。已有缺陷先确认可复现条件，再覆盖与根因相关的相邻边界。

证据取得后，按前述判据判断结果。留白、样式覆盖、位置变化与退出限制本身不自动构成缺陷，应结合页面角色、设计意图和状态契约判断；缺少既有规则时按相关专项技能判断体验问题或报告契约歧义，不从本表推导新的设计约束。

## 证据能支持的结论

| 证据 | 可以支持 | 不能单独证明 |
|---|---|---|
| 规范、源码、定向测试 | 契约内容、实现路径及相应逻辑行为 | 实际外观、原生手势或完整软键盘行为 |
| DOM/状态读取、脚本派发事件 | 对应状态与处理逻辑在该环境中的结果 | 实际命中、指针捕获、触摸取消、惯性、原生焦点或软键盘往返 |
| 计算样式、几何边界、截图 | 当前版本在给定视口、主题和状态下的呈现 | 未操作的状态转换或其他终端行为 |
| 真实点击、输入、滚动与状态切换 | 已实际触发并观察到的交互结果 | 未覆盖平台、状态或消费者均正常 |

- 视觉比较先对齐版本、视口、主题、内容和状态。对字号、对齐、遮挡等问题结合几何或计算样式与可观察结果判断；共享 class、类型检查或 CSS 文本断言不能替代呈现证据。
- 确认当前页面实际加载版本；源码更新、服务启动或安装图标存在都不能单独证明版本已切换。涉及 PWA 时结合页面资源与 SW/缓存证据，不能仅凭 SW 更新推断页面资源已更新。
- 说明影响结论的内容规模、数据来源和关键前置状态。模拟数据可验证相应呈现与交互，不能证明真实接口、权限或保存闭环；实际业务入口的结果不能仅由原型或 Mock 推断。
- 分别记录桌面模拟视口、原生模拟器、设备浏览器、镜像和安装版。焦点或镜像输入工具栏不等于完整软键盘；桌面手机尺寸窗口不证明原生惯性与触摸行为。平台限制须有目标版本的官方资料或实测依据。
- 工具返回成功或指针移动不等于交互发生。无可观察变化时检查窗口、焦点与控制通道；纠正无效后停止重复操作，保留已证实部分并说明缺口，不猜测锁屏等原因。

## 共享消费者与结论

- 先追踪受影响的真实消费者与局部覆盖，再按差异选择代表性场景，如新建与编辑、页面与弹层、活动与隐藏后返回、相关主题与断点。一个默认使用点通过不能代表所有差异场景。
- 分开说明规则是否成立、源码是否遵循、页面是否实测。无法运行时输出静态结论；工具受限或用户豁免的部分仍标为未验证，明确范围，不能推断通过。
- 报告实际操作、观察结果和未覆盖项；失败修复后复测相关路径，不通过追加一条重复规范代替修实现。
- 实测结论须对应最终相关源码及实际加载版本；后续修改使证据失效时，重新验证受影响场景，未受影响的有效证据可复用。
- 适用必测场景未完成、已发现的必改问题未解决或证据不足时，不判页面验收通过；分别说明已完成检查、实际结果和未验证项，不能把计划或工具调用成功写成验证结果。

## 多维审核协作

- 按问题判据确定主归属：用户可观察的体验缺陷归 UX；已有设计契约的违反归合规；重复实现、抽象与维护分叉归复用。业务算法与领域规则转交业务审核。
- 同一根因和修复点合并为一个主问题，关联其他维度的证据与影响；独立根因分别报告。复用已有截图与操作结果，不为每个技能重复采集。
- 问题定级沿用所属技能标准；契约违规即使视觉影响小也保留合规定级。综合结论不能用 UX 通过掩盖未解决的契约或复用问题。
- 审核只产出结论；已获修复授权时，在授权范围内修改并复测。发现问题不自动授权修改规范以迁就实现。
