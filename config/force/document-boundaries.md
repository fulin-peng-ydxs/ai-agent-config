# 产出文档的边界声明与审查

## 文档边界

本文统一维护文档生成、更新与审查的内容归属、权威引用和边界声明规则，适用于说明、规范、需求、计划及分析报告。结构、内容保留与读者验收由 [文档结构与输出规范](document-output.md) 维护，目录和写入授权由 [AI 协作约束](collaboration-rule.md) 维护。只约束已授权的文档工作，不因此新建文档或扩大审查范围。

## 权威维护与消费

- 按规则的对象和职责确定唯一正文位置：跨项目通用规则在全局规范，项目事实与例外在项目文档，技能选择与流程在技能入口，产物格式及内容要求在所属权威模板。文件名称或层级本身不能证明权威，具体要求的适用性与优先级仍按协作规则判断。
- 同类产物的目录、字段、填写要求、条件槽位和内容验收只在一个权威模板维护；技能入口维护执行流程及读取时机。跨技能共用语义引用已有共用契约，取证规则留在专项参考，不建立平行目录、字段说明或状态枚举。上游不复制下游细则，索引只维护用途和入口。
- 消费方可以保留执行所需的触发提示、必要摘要和本地差异；须能定位权威正文，摘要不得形成独立口径或完整副本。删除重复正文前确认来源适用且执行分支实际可达；来源缺失时说明当前承载位置，不把必要内容直接删成链接。
- 规则变更先维护所属正文，再更新受影响的调用、模板、摘要、链接及检查器。发现冲突须核实来源和有效要求，不能以“更具体”或“去重”为由保留无依据的重复定义。

## 写入文档

- 长期维护文档默认在开头设置“文档边界”章节，写明主要用途、负责维护的事实或规则，以及容易混入但应由其他文档承载的内容。
- 结合实际文档关系注明权威来源、深入阅读入口及变更时应更新的位置。只链接已确认存在的来源；尚无独立承载文档时说明当前归属，不编造链接或为凑分工新建文档。
- 短文档、一次性报告和薄入口可将边界并入开头的用途或范围说明；报告同时说明对象、时间或版本范围，避免快照被当成长效规范。
- 已有“职责”“用途与范围”等同等说明时直接复用；补充受文档输出规范的更新边界约束，范围外缺口在交付中报告。固定机器契约或用户指定格式优先，在允许的说明位置表达边界。
- 声明必须针对本文的具体职责，不能照抄“避免重复、明确边界”等写作要求。区分文档内容归属与业务功能范围，两者不能互相替代。
- 仅供生成时读取的规则提示、占位符和本机路径不写入面向项目读者的业务文档。

## 共用声明骨架

本节只维护声明的内容要求，具体格式随所属产物模板维护，不另提供可自由组装的骨架：

- 持续维护文档说明读者、用途、负责的事实或规则、适用范围及关联权威入口。
- 分析与审查报告说明对象、代码/版本或采样范围、实际检查时点、结论与证据状态及未验证限制；不能用生成时间代替检查时间。
- README 导语、技能职责、报告概览等具体落点由模板固定；薄入口指向真实权威正文。没有独立来源时说明当前归属，不编造链接。
- 简短对话结论按范围说明表达，不强制套正式文档；保存和局部更新遵守文档输出规范的保留边界。

## 内容取舍与验收

- 判断内容是否直接支持本文读者理解、决策或操作；仅与主题相关不足以成为收录理由。
- 交付前核对产物中的用途、维护内容和关联归属是否具体、入口是否真实，再对照正文检查越界展开、重复定义、无用途填充或本职责必需信息的遗漏；不能以技能或模板外已有声明、或存在章节标题代替产物的语义核查。
- 审查问题应指出具体内容、影响及建议归属。既有文档没有独立标题但边界清楚时，不单凭标题缺失判错；只审查时给建议，不擅自改写。
