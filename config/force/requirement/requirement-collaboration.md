# 需求协作共用契约

供需求闭环、正式需求、页面原型和开发计划技能读取；维护共用调研、继承、范围、页面协作及交接规则。阶段流程、编号与执行状态由所属技能维护，产物结构、字段及内容验收由各自唯一模板维护。

相关规范：[协作规则](../collaboration-rule.md) · [文档编写规范](../document-output.md) · [测试规范](../testing-standards.md)。分别承接授权、成果编写与维护、验证及证据要求。

## 事实与继承

- 按用户指向、内容语义和可证明的文档关系选择当前输入及上游成果，不绑定固定文件名，也不把同目录材料自动当作上游。保存对象以用户指向成果及后续有效修正为准，多个候选无法判断时才确认。
- 围绕本次链路核实代码、页面、接口、数据、配置、权限和测试，记录影响需求或方案的来源、字段与状态。区分实现事实、已确认结论、推断和未决；代码不能单独证明业务必须如此。解释关键领域术语与口径，可核实的事实不交由用户拍板，访问受限时记录缺口。
- 继承上游功能点、入口、流程、状态、数据、权限、异常、范围、建议项状态及确认结论，不重跑已完成分析或发散平行需求。新事实与既有结论冲突时，定位依据、影响及待决选择；跨文档只保留本阶段所需摘要和追溯。
- 复用有效项目规则与同类能力，确需新增抽象时给出现有能力不足的依据；业务要求、内部实现选择和实际验证证据分别承载。

## 页面内容与变更同步

页面内容按当前阶段维护，跨产物保留必要摘要和可定位引用，不在多处独立定义同一规则：

| 承载位置 | 维护内容 |
| --- | --- |
| 需求闭环 | 页面职责、业务入口、关键操作与反馈、权限、状态、结果消费及失败恢复，达到业务闭环判断所需深度。 |
| 正式需求 | 承接有效输入，维护业务规则、页面行为与关键布局约束、可观察验收条件，形成正式契约。 |
| 原型 | 在有效需求与设计约束内维护具体区域层级、控件位置、操作路径和状态呈现；需求保留结构摘要、关键约束与对应页面/区域引用，不再复制完整线框或交互说明。 |
| 开发计划 | 组件与模块、数据/API、状态/事件的实现关系、任务依赖、开发步骤、验证安排及实际结果；引用需求与原型，补实施差异。 |

页面方案优先复用本次范围内有效的原型、独立设计方案或既有页面契约，需求和计划引用对应位置并补本次差异。原型必要性按 [原型必要性与交接](#原型必要性与交接) 判断；无需原型时，在需求的页面字段补足文字方案。没有正式需求而进入开发计划时，由计划承接有效会话或闭环输入中的行为、必要页面方案与验收条件，不因此补建 PRD。探索稿和局部原型仅作为其明确覆盖范围的依据。

摘要与引用用于下游承接，不要求将既有成果改写为摘要或迁移其有效详情；内容更新沿用原有基线与确认状态。

变更先定位所属内容，再沿真实引用和消费关系核对影响，按下表同步受影响部分：

| 变化 | 同步方向 |
| --- | --- |
| 业务范围、操作、权限、业务状态或验收行为变化 | 更新正式需求或当前有效业务输入，并核对仍在维护的闭环结论、页面方案、计划任务与验证项。 |
| 布局与交互呈现变化 | 更新当前有效页面方案，并同步受影响的需求约束、验收及实施任务；涉及业务变化时同时按上一行处理。 |
| 内部实现变化 | 更新计划方案、任务与验证；影响外部行为或页面呈现时，再同步相应上游内容。 |

同步限于实际存在且受影响的在维护材料，不因同步补建产物或新增台账；授权、保存和归档沿用前述通用规范。未能同步的具体位置、差异与影响由交付说明或调用方现有未决位置承接。

## 原型必要性与交接

正式需求生成或更新、开发计划与实施共用以下原型判断和交接规则；专业模式另须满足 [模式规则](~/.codex/skills/development-workflow/SKILL.md#普通模式与专业模式) 的材料前置或用户明确豁免，不能以现有页面依据替代该前置。仅保存已有成果不触发原型补建。

- 用户要求原型或当前阶段有适用原型前置时，制作或复用覆盖本次页面及变更范围的原型。已有适用成果、格式选择和有效确认直接继承；用户明确不制作时记录替代依据与剩余歧义，不能把未答当作放弃。
- 其他情况先核对需求、现有页面、设计规范和已确认方案；足以确定布局、信息结构与关键交互时，说明依据并推进已授权工作，不询问原型格式。不因新增页面、编写 PRD 或触及样式、文案、字段、显隐、校验而强制制作，按实际影响判断。
- 存在实质未决选择时，先调研并提出具体方案及差异；确需原型比较或走读才能决定时，说明评审目标并进入原型协作。常规细节自行判断，非阻塞探索不影响已确定工作，未解决的关键选择只阻塞依赖部分，不能用假设冒充实施依据。
- 确定需要制作或更新后，读取 [页面原型技能](~/.codex/skills/frontend-prototype-design/SKILL.md)，传入页面及变更范围。由该技能继承或询问形式选择并完成制作与验证；形式未定时不生成，继续不依赖它的工作。HTML 与结构图均可，原型不得擅改业务范围。
- 调用方承接实际路径、页面/区域、格式、验证状态及需同步结论。原型缺失、验证失败或环境受限时，说明影响及下一步，不虚构引用或宣称页面验收通过；保存和局部更新仍遵守原操作范围。

## 确认与推进

- 承接或转换上游成果时，对改变目标、范围、交付形态或既有契约的条目保留授权来源及确认状态；同时核对交付入口、保持项与允许变化。授权有效性及常规细节处理遵循协作规则，不因上游编号或标签跳过核对。
- 上游把推断写成要求，或与用户有效指令冲突时，不直接分解成下游任务；依据既有授权修正受影响条目和引用，实质选择未定则阻塞依赖部分。交付前对照用户要求及这些保持项、变化项，不只对照 AI 自己形成的文档。

| 未决类型 | 阶段处理 |
| --- | --- |
| 阻塞选择 | 缺失结论使当前成果无法成立，或实质改变范围、流程、状态、权限、数据/接口、方案或验收；说明影响、推荐及理由，等待选择后再推进依赖部分，其余工作继续。 |
| 非阻塞未决 | 不影响当前阶段成立，记录影响、确认时点和依赖；用户未答不等于同意，到达依赖点仍未解决时转为阻塞。 |

先核实事实再分类，有项目依据、低风险且可回退的常规细节自行处理，技术细节本身不构成业务确认理由；按影响分批提问，不设置机械数量。保存当前阶段草案须保留假设和未决状态，不能据此标为最终确认或启动依赖实现。当前阶段完成不自动授权下一阶段、生产开发或其他产物；阶段切换依用户请求和对应技能触发规则判断。

缺口关联到具体的决定、条目、结论或环境操作，说明当前仍可推进什么。交接保留上游的确认时点和依赖，不能把交付前必需的信息推迟为执行时再补；依赖尚未满足时可交付标明限制的草案，不能称最终成果已完成。前置依赖须在对应阶段实际可取得，不用下游实施或验证完成作为形成上游标准的条件。

## 范围与交接

- “必须实现 / 建议实现 / 暂不实现”互斥，同一项只登记一次。建议项状态统一为 `本次纳入`、`后续建议`、`已实现`、`待确认`、`不纳入`；`已实现` 须有真实证据。获准纳入的建议属于本次验收范围，保留建议来源即可，不再复制成另一份必须项。
- 按当前阶段保持功能点、需求项、页面功能点、开发任务及验证项可追溯。闭环结论、正式需求契约、计划实施结果和实际验证证据各有维护位置，不混写成同一状态；写入前后核对阶段范围、确认状态和受影响引用，默认文件名由阶段技能维护。
- 识别适用的缺陷修复、重构/升级、数据迁移/补数/修复、异步/第三方、从零建设或技术验证；允许组合，按所属技能把条件要求落实到当前阶段条目及验收，不重建整套阶段材料或专项文档。只写“已考虑”不足以交接，领域口径须有项目或专项依据。
- 从零建设以目标、外部约束和已确认选择为基线，待建设与无法访问分别表达；技术验证须明确假设、边界、停止判据及结论适用范围。假设被证据否定也可以完成验证交付，未执行、证据不足与实验操作失败分别记录，不能混作否定结论；验证成功不等于生产可用。
- 性能、安全和兼容性按本阶段用途判断；闭环阶段展开影响业务成立的边界，不为共用契约额外增加专章或固定字段。实质目标或风险在所属条目展开，低风险简述依据，不虚构指标或引入无必要设施。指标或生产条件缺失只阻塞依赖它的设计决定、达标结论或环境操作，候选参数不能冒充业务承诺。需求保留假设和可观察标准，实验实现步骤由开发阶段承接。
- 首次完整形成成果或获准补全时，沿一条代表性场景连接前提、操作、反馈、数据/状态、交接与失败恢复，检查本阶段产物能否支持下一步判断。示例只解释既定规则，不新增需求或充当实现、验证证据；已有成果覆盖时直接复核，不为走读另写一份或扩写保存基线。
