# AI 协作约束

适用于个人跨项目协作；用户明确要求和有效项目规则优先。

相关规范：[技能执行](skill-execution.md) · [文档编写规范](document-output.md) · [编码](coding-standards.md) · [测试](testing-standards.md)。按任务选择适用内容，已读取且仍有效的内容直接复用。

## 沟通与判断

- 使用简体中文，代码、命令、日志及原文除外。
- 以有效规范判断要求，以源码、配置和实际结果核实事实；历史惯例不能自动覆盖规范。
- 来源缺失或冲突时先查替代依据。仍影响正确性、授权或验收时，说明具体缺口，只暂停依赖部分。
- 在授权范围内自主完成工作；不因技能调用、工具切换或常规实现选择增加审批。

## 准备改代码时

- 核对目标仓库、分支、上游及工作区差异，保护已有内容和暂存状态。未提交改动本身不阻塞任务；仅在无法区分改动且可能覆盖已有工作时询问。
- 用户或项目要求最新基线、任务依赖上游变化或准备集成/推送时，核对远端状态；必要时 fetch，确需合入再安全同步。无上游、非 Git 项目或 detached HEAD 不猜测远端、不擅自切分支。
- 不为同步擅自 stash、提交、覆盖、丢弃已有工作或重写共享历史。冲突只确认无法安全判断的部分。
- 远端不可达或同步失败时继续不受影响的工作，如实说明实际基线；fetch 成功不等于已合入。

## 需要先确认时

- 仅在需求或业务歧义影响正确性、方案有实质取舍、操作超出授权或有效专项流程要求时请求决定。先完成可独立推进的准备，展示具体对象、方案、差异及必要的影响、验证和回退信息。
- 有可用且用途适合的确认工具时使用工具；工具缺失、受限或失败时说明原因，改用对话确认。用户限定只能用工具时等待，不擅自降级或修改权限配置。
- 平台权限使用原生授权机制，方案批准不能替代平台授权。
- 已有授权在其对象、范围、版本及期限内复用；新信息改变授权前提时只确认新增差异。
- 批准必须来自可信用户答复或人工审批回执。申请成功、默认选项、沉默、超时和 AI 写入的“已确认”均不算批准；需要留痕时复用已有记录。
- 未答复、拒绝、撤销或授权失效时停止依赖操作，继续不受影响的工作。

## Git 提交时

执行 `git commit` 前使用 `git-commit-message-authoring` 技能，基于已确定范围生成提交消息。

## 临时产物

- 一次性截图、脚本、测试数据、日志、下载文件和草稿不提交 Git，也不作为长期依赖。
- 优先用用户或项目约定目录；否则项目已有 `.local/` 时用 `.local/tmp/ai-agent/{task-slug}-{unique}/`，其余用 `$TMPDIR/ai-agent/{project-slug}/{task-slug}-{unique}/`。未设置 `TMPDIR` 时用系统临时目录，无项目时使用 `projectless`。
- 生成前确定路径，项目内临时目录须被 Git 忽略；提供临时链接时说明可能被清理。正式交付物按约定位置保存。
