# 文档结构与输出规范

## 职责与适用范围

本文统一维护文档生成、保存、更新与重构的结构策略、内容完整性和读者验收规则，适用于说明、规范、需求、计划及分析报告。各类产物的具体内容与格式由对应技能或项目输出契约维护；内容归属与引用遵循 [文档边界规范](document-boundaries.md)，目录和写入授权遵循 [协作规则](collaboration-rule.md)。本文不新增交付物或扩大任务范围。

## 模板与结构选择

模板中的“（适用时）”仅提示该项有触发条件，不是自适应开关；没有此标注不代表标题、顺序或整个模板固定。“必须覆盖某项内容”也不等于“必须单独设同名章节”。依据完整输出契约判断，不能只解析标题括号。

### 结构策略与内容要求分开判断

| 结构策略 | 执行方式 |
| --- | --- |
| 参考结构 | 提供组织示例，允许按读者任务合并、调序、改名或增加章节；主要说明对象、最低内容和信息粒度保持稳定。既有模板未声明策略时按此处理；新建或整体重构的输出契约须明确策略。 |
| 默认骨架 | 首次完整生成默认沿用给定标题、层级和顺序；按契约声明的条件省略、合并或展开。契约未列出的调整须有具体的对象关系、重复内容或阅读障碍依据，不因篇幅偏好、输入简短或文风变化临时重组。调整后仍形成完整正文。 |
| 固定结构 | 明确锁定的标题、编号、顺序、字段或格式须保留，其余部分仍可适配；固定一个字段不等于固定全文。依据应来自有效机器契约、用户/项目要求或技能明确规定的稳定输出契约，不能仅因模板存在就推定固定。 |

核心内容必须覆盖；条件内容在触发条件成立时必须覆盖，并非可随意省略；增强内容只在有依据且有实际用途时补充，不为凑章节扩需求。核心、条件、增强是内容要求，与以上三种结构策略独立：固定结构也可能包含条件内容，参考结构也有不可遗漏的核心内容。

### 输出契约的最低定义

创建或整体重构生成文档的技能、模板或项目输出契约时，在实际承载产物要求的位置明确以下内容；不要求新增文件或另建同名章节：

- **用途与组织单元**：面向谁、用于什么判断或操作，以需求、任务、问题、机制等什么对象承载详情；总览、详情、状态和证据各放在哪里。
- **稳定内容**：每个组织单元的最低信息、必要标识及字段含义；条件内容写明可判断的触发条件、成立时的最低信息及不成立时的处理。不能只写“按复杂度展开”或“适用时填写”。
- **结构与调整边界**：明确采用“参考结构”“默认骨架”或“固定结构”；不同部分采用不同策略时分别说明，不能仅列目录或写“按需调整”。给出默认组织或明确的格式，说明允许合并、省略或展开的条件及调整后仍需保留的内容；固定项注明依据和适用范围。
- **验收判据**：读者应能作出的判断、完成的操作和可定位的依据；区分格式检查、内容核对及实际运行验证，各自证明什么。

策略及结构调整边界跟随完整产物结构维护：有独立产物模板时，在模板自身的生成说明中声明，技能正文及其他契约引用该处，不另设平行定义；没有独立模板时，在实际承载结构的输出契约或技能内联要求中声明。嵌入片段沿用主体策略，只补充自身固定项或差异；策略声明供生成时读取，不作为写作提示复制到交付文档。

同一类产物在相同范围和适用条件下，组织单元、字段含义和信息粒度应一致；措辞可变化。范围、条件或有效要求改变时才作相应调整，不把结构稳定误解为所有文档使用同一目录，或每次生成逐字相同。

### 选择与裁剪

1. 先区分首次生成、保存、局部更新或获准重构。用户只要求摘要或提纲时按该范围输出，不擅自扩为完整文档。保存和局部更新沿用有效原结构及信息粒度，保留细节、引用和确认状态；可修正格式、指代和措辞、去掉寒暄与执行预告，明确逐字保存时保留原文。不得借新模板扩写、删减或重排授权范围外内容。
2. 确定用户目标、读者、交付范围及实际能力/风险，读取适用输出契约和已存在的校验约束。按有效规则优先级确定结构，保留明确固定项；无法消解且影响交付的冲突须说明，不自行选较宽松版本。不能仅按用户输入字数判断复杂度。
3. 按事实判断条件内容是否适用，再决定承载章节、表格、图示或条目。条件不成立时可省略；容易误认为漏项或影响范围、风险、验收时简述依据。固定结构明确保留的槽位按契约标注“不适用”及理由，不强行填充。
4. 未知、无访问权限、待确认和未验证均不是“不适用”；在原位置或集中未决区记录缺口、影响与后续处理。核心主题确无对应对象时说明事实，不编造能力或结果。
5. 合并章节不降低条目粒度、证据和可操作性：各需求、任务、风险或验证项仍独立可辨识，保留本类型规定的适用字段、编号、状态与追溯。共用规则集中说明，条目引用并补差异；不能用概述、空表或“同上”代替实质内容。
6. 更新将有效补充融入所属位置，不靠追加聊天全文、旧稿或重复附录代替整合；实质冲突保留待决状态。授权范围外的必要缺口在交付中说明，不借检查补写范围外内容。

## 面向读者的组织与审阅

首次生成或获准重构时按下列原则组织内容；保存、局部更新和固定结构仍遵循前述边界。不统一各类文档的目录或章数；审批文档侧重决策路径，操作文档侧重执行路径，规范与参考文档保留主题检索能力。

- **判断入口前置**：开头说明读者要判断或完成的事项及范围；分析和决策材料按实际需要给出当前结论及关键分歧，规范和操作文档给出适用入口。未确认或未验证的结论标明状态，不为摘要提前下结论。
- **依据贴近结论**：在需要作出选择或判断的位置给出必要事实、来源及限制，区分事实、推断和已确认决定；证据索引只提供深入定位，不替代就地解释。
- **围绕读者处理的对象组织**：将同一对象的目标、行为、边界、结果及判断条件就近表达；具体组织单元由所属技能定义，不能只减少主标题却把原有分类拆分搬到每个条目内部。
- **共用与局部分工**：跨对象共同生效的内容集中维护，条目引用并补差异；局部条件留在所属对象。保留自足理解与操作需要的上下文，不把正文压成链接目录，也不把所有细节塞进一张宽表。
- **信息作用清楚**：事实解释依据、规则定义行为、步骤指导操作、标准用于判断；各自维护位置按文档边界规范确定。
- **沿阅读路径复核**：按目标读者走读一个代表性对象或完整流程，确认能作决定、知道下一步与成功判据，并能定位疑点或失败的依据、归属及处理入口。检查重复、断链和缺少上下文，不以标题变少、字数减少或链接齐全代替内容验收；走读不是实际运行验证。

## 工程类文档的执行要求

技能、规范、配置说明和操作手册按消费方的实际任务编写：

- 先明确输入、判断分支、动作、结果和异常出口，再选择章节；每条规则应改变一个可指出的执行决定。删去某句话不影响判断、操作或理解必要依据时，优先删除。
- 能用配置、命令、差异、接口或判定表直接表达的内容，给出实际形式；说明只补适用范围、参数含义和必要取舍。不用分类介绍代替具体规则，不用主题清单代替操作步骤。
- 操作须能查到执行位置/身份、前提、精确命令或步骤、成功判据及失败后的下一步。未知写具体缺项和影响，不反复用“待确认、注意风险”代替事实；完整细节只维护一次。
- 每个文件和固定字段须有实际读者、消费入口或检查用途；没有程序消费需求，不为显得规范而新增 schema、状态 JSON 或多级文档体系。需要稳定重复判定时，优先复用或实现小型检查器并验证有效与无效输入。
- 验收用真实或代表性输入走通任务；只有原则、章节和引用，仍无法决定下一步或完成操作的产物不合格。不以字数、模板齐全或格式通过替代这个判断。

这些要求约束可执行内容，不将需求分析、技术解释或研究报告压成命令清单，也不删除理解复杂问题所需的依据。

## 文档校验

标题、顺序或字段的强约束只针对已声明的固定项或实际机器契约；参考结构和默认骨架不能因校验器硬编码而被锁死。格式、链接、空章节等通用检查仍适用；改变固定约束前核对消费方、比较/引用需求和校验器；调整结构时维护受影响锚点及检查，不为通过校验弱化内容要求。标题匹配不能代替语义覆盖和实际验证。

内容核对须逐项定位核心内容、已触发的条件内容及证据缺口，拒绝只有标题、主题清单或泛泛结论的交付物。对自由文本的语义要求，使用代表性场景走读或有明确判据的产物样例验证；可确定判断的机器契约沿用已有检查器。不得为弥补语义验证而锁死可调整标题，也不得以格式通过宣称内容验收或生成稳定性已经验证。
