# 文档结构与输出规范

## 职责与适用范围

本文维护文档生成、保存、更新和重构的通用契约：固定程度、模板定义、缺失信息和验收。具体格式及内容要求只由所属权威模板维护；内容归属见 [文档边界规范](document-boundaries.md)，目录和授权见 [协作规则](collaboration-rule.md)。不因此新增交付物、扩展任务或将普通对话套成报告；系统及插件自带技能不作为自有模板批量改写。

## 模板与结构选择

### 固定生成原则

模板先设计并验证，使用时只填充事实与分析。自有文档生成技能每类正式产物只有一个默认完整模板；目录、标题层级及顺序、字段名称及顺序、表格列和内容落点固定。不得按篇幅、输入长短、对象多少或阅读优化临时合章、改名、调序、增删字段、互换表格与段落。旧称“参考结构”“默认骨架”不再作为新文档的自由组织策略。

生成时仅允许替换明确的内容占位、增减模板标出的重复条目，以及执行明列的条件分支。段落可以充分解释复杂机制，不改变所属位置；未声明的章节或附录不得自行添加。模板不够用时指出具体缺口，结构变化回到模板维护任务处理，不在单次生成中临时设计或自行新增模板变体。

用户指定格式、有效项目契约按协作规则的优先级处理，说明实际消费来源；已有同类文档的偶然写法不自动成为例外。摘要、提纲或局部分析仅在用户明确要求或技能已有明确模式时交付，不由模型自动选择简版。没有可用模板时先报告缺口，不将自行组织的正文称为符合固定模板的正式交付。

### 输出契约的最低定义

每类产物的唯一权威模板同时维护：

| 定义项 | 必须明确的内容 |
| --- | --- |
| 用途与归属 | 读者、判断或操作目标、维护对象、范围和权威来源；在交付骨架中有实际承载位置 |
| 完整结构 | 可直接填充的主体、标题层级及顺序、固定字段、表格列、重复条目与编号，不只有目录或覆盖清单 |
| 字段内容 | 每个条目必须回答的问题、最低信息、证据位置和不能混入的内容；共享状态/业务语义引用共用契约 |
| 条件与缺失 | 触发依据、成立时填写内容、不成立时固定表达、未知时缺口及影响，不用“按复杂度展开”等无限判断 |
| 验收判据 | 机器可判断的格式条件，以及读者能完成的判断、操作和可复查证据；说明格式检查的证明边界 |

模板中的填写说明与交付骨架分开，说明、占位符、重复标记和生成工具本机路径不得泄漏到产物。多技能共享的语义由既有共用契约维护，模板引用；取证方法和执行流程留在技能或专项参考，不再各写完整目录、字段解释和状态枚举。

### 条件槽位与重复条目

- 条件章节和字段默认保留位置；事实确认不涉及时填写“不适用：原因”，没有发现时填写“无：已检查范围及依据”。无记录不创建虚构条目或空数据行。只有模板明确声明且有确定条件的分支才可改变相应局部结构。
- 未知、待确认、无访问权限和未验证分别如实填写，注明缺项、影响及后续入口；均不等于“不适用”，不得删掉槽位或用模板示例补事实。
- 需求、任务、风险、页面等重复单元沿用同一字段结构；按模板规定排序，稳定编号不因排序重编。不合并独立对象为概述，不以总览表代替详情。
- 长说明留在所属字段或段落，图、代码和表格仅放模板声明的位置。共用事实只维护一处，条目引用具体位置并补差异，不用“同上”省掉理解与操作必需的上下文。

## 保存、局部更新与重构

1. 先确定首次生成、保存、局部更新或整体重构。新建和获准整体重构使用固定模板；用户明确只要摘要或提纲时遵循该范围。
2. 保存和局部更新保留有效原结构、粒度、细节、引用及确认状态，不借新模板重排或补写范围外内容。逐字保存原样保留；非逐字保存可修正格式、指代和措辞，移除寒暄与执行预告。
3. 已采用固定模板的文档，新增条目按同一模板填写；旧文档的局部更新仅核对受影响内容及现有约束，不用全文模板检查强迫迁移，也不以局部检查宣称全文合规。
4. 有效补充融入所属位置，不追加聊天全文、旧稿或重复附录。实质冲突保留待决状态，范围外缺口在交付中说明。整体重构维护受影响锚点、消费方和检查器。

## 面向读者的内容验收

模板设计时固定判断入口、详情对象、证据和未决位置，运行时不再重组：

- 开头给出范围及实际结论或适用入口，未确认和未验证明确标状态；不为摘要提前下结论。
- 同一对象的依据、行为、边界、结果与判断条件就近表达。事实、推断、已确认选择和实际运行证据分别标明，证据贴近其支持的结论。
- 不用主题清单、关键词、空表、泛泛建议或仅有标题的文档冒充完整正文。固定格式不限制必要解释深度，不用逐字相同或字数判断质量。
- 沿代表性对象或完整流程走读，读者能判断、操作、知道下一步与成功判据，并定位失败依据、归属和处理入口。走读不冒充实际运行验证。

## 工程类文档的执行要求

技能、规范、配置说明和操作手册按消费任务编写；这些要求约束内容，按所属模板承载：

- 明确输入、判断分支、动作、结果和异常出口，每条规则改变可指出的执行决定；不写无作用的原则、自我评价或重复提示。
- 能用配置、精确命令、差异、接口或判定表直接消费的，提供实际形式，说明只补范围、参数和必要取舍。
- 操作须能定位身份/目录、前提、命令或步骤、成功判据和失败后的下一步；未知记录具体缺项及影响，不用反复“另行确认”代替可查事实。
- 每个文件和字段有真实消费入口或检查用途，不为形式新增 schema、状态 JSON 或多层体系；稳定重复判断复用小型检查器。
- 用真实或代表性输入走通任务；只有原则、章节和链接而无法执行的内容不合格。技术解释与分析报告仍保留理解复杂问题所需的依据。

## 文档校验

固定格式是可检查契约。检查器从权威模板取得结构，不另维护一份标题、字段和表格列清单；共用解析能力集中复用。验证缺章、错序、缺字段、非法新增、错误条目格式、空值、占位符残留及表格列，保留合法与违规样例。模板变更同步消费方及测试，不为通过检查放宽要求。

格式、内容与实际行为分别报告：格式通过不证明事实正确或链路成立；内容按字段要求定位证据和缺口，再走读适用场景。生成稳定性验证使用简单、复杂、条件不适用、信息缺失及适用的保存/局部更新场景，单次样例不能宣称多轮模型输出稳定。没有执行的验证如实说明，不宣称验收通过。
