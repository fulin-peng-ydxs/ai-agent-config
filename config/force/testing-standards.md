# 测试规范

## 文档边界

本文面向安排、执行验证或判定验收结果的 AI Agent，统一维护跨项目的验证层级、测试与门禁维护、服务状态保护，以及前后端编译、构建和实测的触发要求。具体命令和业务判据由有效项目规范维护；协作授权与临时产物管理由 [AI 协作约束](collaboration-rule.md) 维护，编码要求见 [编码规范](coding-standards.md)，页面场景、证据与完成条件由 [前端验证规范](frontend-verification.md) 维护。

安排、执行验证或判定验收结果时必须读取本文；代码改动实施前一并读取，用于确定验证范围，不要求尚未实现时执行测试。文档和规范改动按本次风险选择差异、链接、语义或适用检查器验证，不因此执行无关代码测试。本文是测试执行要求的唯一全局正文，变更时同步受影响的入口和技能引用，不在技能或其他工具目录维护正文副本。

## 验证选择与门禁维护

- 所有代码改动先自审，再在能证明风险的最低层执行最小验证；默认不跑全量测试、完整构建或多视口 E2E
- 行为变更依据 [编码规范](coding-standards.md) 中本次受影响的契约，选择正常路径及会改变结果的失败、边界场景，验证可观察结果和必要副作用；涉及写入时核对失败后的数据与状态，涉及重试或重复请求时核对重复执行结果，涉及敏感信息时核对实际输出边界。不以存在异常捕获、日志调用或校验代码代替行为验证
- 根据本次变更检查测试与门禁的覆盖缺口；已有能力直接复用，覆盖不足时补充或更新相关测试。规范约束已有检查器时，契约变化同步维护检查器及合法、违规样例；同职责的新增检查优先扩展既有入口。无适用检查器时，仅在规则可稳定自动判断，且存在重复执行需求或明确的确定性收益（如高风险误操作防护）时新增，并接入既有执行入口；一次性低风险文档或措辞修改可用差异检查和定向走读验证，不附带建设新门禁。按风险执行适用验证，报告结果及未验证项；必要检查未通过或未执行，不得宣称验收通过
- 不得仅为获得通过而删除或弱化断言、扩大豁免、跳过检查或降低规范以迁就违规实现。确有契约变更、测试错误或合理例外时，说明依据，按实际影响维护规则、检查器与正反例；修正测试或检查器不等于需要放宽规范，调整后仍须拒绝应拦截的违规

## 服务状态保护

- 验证涉及服务状态时，先记录原运行状态及恢复所需的模式、参数和环境，不记录密钥。优先使用项目既有服务脚本；原本运行则结束后恢复原运行方式并检查健康，原本停止则保持停止，用户另有要求时除外。需要加载本次改动时按既有授权安全重载或重启；恢复失败须报告实际状态及未完成项，不得宣称完成

## 前端

- 不影响布局与行为的文案、注释、说明和展示属性只做差异与格式检查；纯函数、状态计算、接口和领域规则使用对应的定向测试
- 改动影响页面呈现或操作可达性（如布局、尺寸、滚动、定位、弹层、响应式或内容显隐）时，必须在受影响范围内完成浏览器实测；无法实测时明确未验证范围，不宣称页面验收通过
- 页面验证的场景选择、证据与完成条件统一读取 [前端验证规范](frontend-verification.md)。项目具体契约与各技能专项标准仍由原入口维护，不在各处复制共用验证流程
- 页面临时查看、点击、截图或控制台检查优先使用 AI 工具内置浏览器；未获用户明确要求，不连接其个人 Chrome、Edge 或其他外部浏览器
- Playwright 等长期 E2E 只用于低层测试无法覆盖、稳定且高价值的浏览器关键链路；不因局部交互、样式、文案或单次缺陷修复默认新增 E2E。局部改动符合前述条件时，按覆盖缺口复用、扩展或新增必要用例
- 完整构建只在构建配置、依赖、路由或懒加载、全局资源、发布产物受影响，项目明确要求，或用户要求时执行；源码未再次变化时不重复运行同一验证

## 后端

- Java 源码、依赖或构建配置改动后，使用项目既有命令执行适用的编译校验；涉及行为变化、缺陷修复或边界风险时，补充或更新必要测试并执行定向回归，不以“业务是否复杂”决定是否验证
- 分别说明编译与测试结果；跳过测试的编译或打包命令不能证明测试通过，未执行的测试及其影响须明确报告
