# 测试规范

页面验证参考：[前端验证规范](~/.codex/skills/frontend-ux-audit/references/frontend-verification.md)。

## 验证选择与门禁维护

- 代码改动先自审，在能证明风险的最低层执行必要验证，覆盖正常及相关失败、边界场景；默认不跑全量测试、完整构建或多视口 E2E。
- 行为变化检查可观察结果和必要副作用；写入验证失败后的数据与状态，重试验证重复结果，敏感数据验证实际输出。存在校验或异常处理代码不等于行为已验证。
- 复用现有测试和门禁，按覆盖缺口补充。规则变化同步检查器及合法、违规样例；仅在可稳定判断且有重复需求或明确防护收益时新增检查器，并接入现有执行入口。
- 文档改动按风险检查差异、引用、语义及适用格式；一次性措辞修改不附带建设门禁或运行无关测试。
- 不为通过而弱化断言、扩大豁免、跳过检查或降低规则。契约变化、测试错误和合理例外须有依据，修改后仍能拦截应拒绝的情况。
- 报告实际结果和未验证项；必要检查未完成或失败，不宣称验收通过。源码和条件未变时复用有效证据。

## 服务状态保护

验证涉及服务时，先记录原运行状态及恢复所需的模式、参数和环境，不记录密钥。优先复用服务脚本，按已有授权重载或重启；结束时恢复原运行方式并检查健康，原本停止则保持停止，用户另有要求除外。恢复失败须报告。

## 前端

- 不影响布局与行为的文案、注释和展示属性做差异与格式检查；纯函数、状态计算、接口和领域规则做定向测试。
- 呈现或操作可达性变化必须完成受影响页面的浏览器实测；无法实测时说明缺口，不宣称页面验收通过。
- 临时浏览、点击和截图优先使用内置浏览器；未经用户明确要求，不连接个人 Chrome、Edge 等外部浏览器。
- 长期 E2E 用于低层测试不能覆盖、稳定且高价值的关键链路，不因局部改动默认新增。
- 构建配置、依赖、路由、懒加载、全局资源或发布产物受影响，或用户、项目要求时才完整构建。

## 后端

Java 源码、依赖或构建配置变化后执行项目适用编译；行为变化、缺陷修复和边界风险补充必要测试并定向回归。分别报告编译和测试结果，跳过测试的打包不能证明测试通过。
