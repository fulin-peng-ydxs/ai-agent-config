# 基础规则
- 具体执行红线统一维护在同级目录 `~/ai-agent-config/config/force/collaboration-rule.md`
- 代码开发、文档编写等相关任务时，必须读取并遵守 `collaboration-rule.md`。
- `collaboration-rule.md` 为最低优先级兜底规则；若本文件、项目规则或用户明确要求与其冲突，优先遵守更具体的约束。

# 技能位置
- 当用户提到 `Codex 技能`、`Codex 全局 skills`、`Codex skills 目录` 时，默认对应本地目录 `~/.codex/skills/`。
- 当用户提到 `Claude 技能`、`Claude 全局 skills`、`Claude skills 目录` 时，默认对应本地目录 `~/.claude/skills/`。
- 当用户提到 `Kimi 技能`、`Kimi 全局 skills`、`Kimi skills 目录` 时，默认对应本地目录 `~/.agents/skills`。
- 处理这三类请求时，优先直接使用上述固定目录，不再重复做全盘查找；除非用户明确说明使用其他目录。


# 文档规范
- 写技能、规范、校验脚本或自动化约束时，只沉淀最新事实和稳定规则，优先抽象出通用不变量。
- 不要把当前案例、具体文档类型、章节编号、标题名称、工具运行目录或临时实现写死，也不要留下迁移说明、来源解释、自我注释或“某内容已放到某处所以这里不写”的流水账。
- 只有稳定对外接口、机器读取契约或用户明确要求固定的字段，才应做结构化强约束。

# 强制要求
- 代码改动完成后，必须按通用协作规则： `collaboration-rule.md`和对应项目中的开发规范：包括但不限于`DESIGN.md`等文档，来审查改动的代码是否严格遵守了对应规则的要求。
- 任何操作完成后，第一，都必须以第三方视角对此次操作进行一次完整流程闭环的自审与修复操作，不然工作不能算完成。第二，必须检查是否需要同步更新相关的开发规范等事实文档
- 用户提出的问题，都必须先进行举一反三，即审查是否其他地方也存在这个“类似的问题”、“改动会影响此功能的其他能力”或“其他潜在没有发现的问题”，一并纳入解决范围里。
